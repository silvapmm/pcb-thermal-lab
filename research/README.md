**How a folder is laid out** (the same everywhere; rules in `CLAUDE.md`, "Research branches"):

* The root holds `README.md` (numbered results; a chapter `N. Review` by the reviewer; last section: what was read and what was not verified) and `INTEGRATION.md` when the work is not yet in the program.
* `figures/` (`fig_NN_topic.png`, committed), `docs/` (text for the project documents), `scripts/` (all the executable Python), `lib/` (shared code, only when needed), `tests/`.

**Figures.** Data figures (`scripts/make_figures.py`) and diagrams (`scripts/make_diagrams.py`, shapes in `diagram_kit.py`) share one numbering per folder and are linked from the README. Check them with `.venv/bin/python research/check_figures.py`; the rules are in `CLAUDE.md` and in the docstring of that script.

**Licences.** Everything of ours here is MIT. The Gerber figures of `gerber-import`, `gerber-models` and `gerber-nets` render our own boards or the MIT Stormduino board; the details are in section 9 of `gerber-import/README.md`. Exception: `gerber-real-boards/figures/fig_08_paste_groups_window.png` renders the top paste file of Manawyrm/ISASTM (GPL-3.0, https://github.com/Manawyrm/ISASTM); that picture keeps the GPL-3.0 licence of the design, with this attribution (the maintainer decides whether to keep it or to redraw it from a synthetic file). No file of a third-party board is committed.

**Research libraries that read the via through `net.gz` (the program changed).** Since `fix/point-via` the FVM no longer adds the barrel conductance of a via to `Network.gz`; it is a set of mean-potential couplings in the matrix (`viawell.py`) and `net.gz_via` holds the point conductance of the cell of the via centre. The four libraries that read the via from `net.gz` (`bare-spot-under-source/lib/layered.py`, `lumped-via-groups/lib/lumped_zones.py`, `via-fill/scripts/study_via_model_checks.py`, `sor-with-via-couplings/lib/sorvia.py`) were updated on `research/via-libs-update`, together with the libraries that compile copies of the program's source (`point-via-convergence/lib/program_patch.py`, `lumped-analytic-vias/lib/lumped_patch.py` and `analytic_patch.py`, `lumped-via-groups/lib/refs.py`); their folder READMEs say what changed and whether the numbers were re-run. The point via of the program up to `f2d5c03` is kept as the `point` copy and as the `off` mode of the patches, tested against values frozen from that commit.
