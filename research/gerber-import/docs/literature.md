# Literature status for the Gerber reader (phase 1)

What was read about the Gerber format and how. The literature of the mapping of copper to cells (Sampson, Blackmore, Guenin) is in `research/gerber-models/docs/literature.md`.

## How the sources were obtained

The environment's network policy denies `www.ucamco.com` (HTTP 403), so the session that wrote the reader could not open the specification; the maintainer pasted the text of the Ucamco *format page* into the conversation (below), and the review downloaded the specification later (README section 7 (Review) and "What was read and what was not verified"). The Electronics Cooling articles, obtained the same way, are recorded in `research/gerber-models/docs/literature.md`.

## Ucamco (the owner of the Gerber format)

* **The specification itself was not read by the session that wrote the reader** (`www.ucamco.com` is blocked for the assistant); the review downloaded revision 2024.05 and read the passages listed in README section 7 (Review) and "What was read and what was not verified". The maintainer pasted the text of the Ucamco *format page* (not the specification). What that page says, in short: layer files represent copper, solder mask, legend, drill and route; **attributes carry meta-information such as whether an object is an SMD pad, a via pad or a fiducial, or the net names of connections**; the **Gerber job file** carries fabrication characteristics such as thickness or finish in a machine-readable form; the format is 7-bit ASCII, "simple, compact and unequivocal".
* What it confirms for us: (a) net names are part of the standard (the attribute `TO.N`), not a KiCad habit, so a net import is legitimate when the CAD tool writes it; (b) the aperture function attribute (`TA.AperFunction`: SMD pad, via pad, fiducial, conductor, ...) separates pads, vias and tracks without guessing, which is what a plated-via and thermal-via import needs; (c) a **job file** exists that could prefill the stack-up (thickness, finish): not read, its fields must be checked in the specification before a design is drawn (idea for `INTEGRATION.md`).
* Resources named on the page, useful for us: the **online reference viewer** (https://gerber-viewer.ucamco.com/, to check a file by eye, needs the maintainer's browser), the **Gerber downloads page** with the specification, **examples of PCB fabrication data sets and test files "to help debug implementations"** (https://www.ucamco.com/en/guest/downloads/gerber-format; the format owner's own conformance material, to be downloaded by the maintainer and added to `data/`, never committed), the offline job editor, and **gerber-writer**, a Python library for writing Gerber files (PyPI; reachable, used in `study_gerber_writer.py` as a third independent writer).
* Checked in the specification (revision 2024.05): aperture holes and exposure off (clear macro primitives) by the review of README section 7 (Review) and "What was read and what was not verified"; by the review of the separation of the three folders, the syntax of `TO.N` (`.N,<netname>{,<netname>}`, the empty name `%TO.N,*%` for objects on no net, `N/C` for a single-pad net), the compatibility form `G04 #@! ...` ("both have exactly the same meaning"), the aperture functions `ViaPad`, `ComponentPad`, `ViaDrill`, `ComponentDrill`, and "attributes do not affect the image". A limit found there: an object may name several nets; the reader keeps only the first (none of the files used has more than one).
