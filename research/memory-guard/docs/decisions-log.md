# Text for the Decisions Log of `CLAUDE.md` (when the feature is adopted)

* **Memory guard** (`feature/memory-guard`, from `research/memory-guard`): one guard by estimated memory replaces `solid3d.MAX_CELLS` and `fvm.MAX_SOR_BLOCK`. The estimate is `base + k N (N / 500 000)^(p - 1)` per class of model (classes by the nodes per plan cell t = unknowns / cells: FVM up to 3.5, 3.5 to 4.5 and above 4.5; FDM up to and above 4.5; 3D solid up to 6, 6 to 12 and above 12; each with a safety factor of 1.11 to 1.46; the Lumped and the Analytic never refuse in the measured range), with coefficients fitted on a ladder of 145 measured points, each point run in its own process with its peak resident memory read from the kernel. The limit is a fraction of the installed memory (70 % by default, editable in Preferences); the verdict ok, slow or refuse is used by `api.simulate`, the jobs, the interface and the command line. No new dependency (os.sysconf, sysctl, /proc/meminfo, ctypes). The block SOR costs 72 n^2 bytes (measured), so `MAX_SOR_BLOCK = 5000` was 1.8 GB. Measured: the layered FVM is linear in the unknowns only for thin graphs (t up to 4.5); a six-layer plain board takes 8.8 GB per million unknowns; the cell-major numbering gave no general gain.
