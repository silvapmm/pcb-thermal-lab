# Text for the project documents when the version comparison is adopted

A research branch does not edit `docs/versions.md` or `CLAUDE.md`; this is the text for the maintainer to apply on the integration branch.

## `docs/versions.md` (one line near the start, under the list of versions)

See `docs/version-comparison.md` for the same 17 boards run on every version from v2.0.0 to the tree: what each version implemented, why the numbers moved, and the error of each model against an independent 3D solver.

## `CLAUDE.md` (structure block, `docs/` line)

Add after `validation.md (...)`: `version-comparison.md (the 17 harness boards run on every version, generated by research/release-regression-245/scripts/regen_version_comparison.sh; regenerate for the final tree of each release)`.

## Regeneration

1. `study_run_suite.py --label develop-tip` on the tree, `study_baseline_release.py --tag v2.4.x --dest <outside the repository>` for v2.4.0 to v2.4.5, `compat_run.py --tag v2.x.0 --label v2.x.0` for v2.0.0 to v2.3.0, `study_references.py`.
2. `PY=<python> sh research/release-regression-245/scripts/regen_version_comparison.sh`.
3. At the release, the tree becomes a tag: add its notes to `reference/version_notes.json` and its table to `reference/`.
