# Review of the severity badges, the explicit warning severity and Run / Stop (2.7.0)

Branch `fix/gui-warning-icons-270` (from `develop` 5bcaf57c): the executor's commits d6122208 (severity), cc77c4e0 (badges), 41008a88 (Stop), 9f709a28 (tests and documents) and 8f2d4c94 (the overlapping-jobs stress test), then the corrections of this review, each with a test that fails without it.

## Verdict

**GO with the corrections below.** The Stop path is sound: one busy state for every calculation, the queued jobs cancelled before the running one, the button back to Run after an end, a failure and a cancel, no process left. The badges are drawn as the maintainer chose (solid amber triangle for an alert, grey circle for a note, beside a plain-text title, no bullet, accessible names) and are centred on the lowercase letters at device pixel ratio 1 and 2 in both themes. Two defects were found in the program and fixed, one test isolation defect and two stale pictures.

## Findings, by severity

1. **Defect in the program, a double click on Stop started a new run** (fixed, `MainWindow._on_busy`, `_release_run_hold`, `SolverPanel.set_hold`). The cancel is synchronous, so the button under the pointer is Run before the second click of a double click arrives. Reproduced offscreen through the real window with a press, release, double-click and release: on the dock button a new simulation was queued (busy, one job); on the toolbar the Run tool button that replaces Stop received the second click and started a run as well. Now Run (dock button and the action, so F5 and the toolbar too) stays disabled for one `QApplication.doubleClickInterval()` after a Stop and comes back by itself; a direct call of `run_simulation` (the API of the tests) is not held. Test `tests/test_gui_stress.py::test_a_double_click_on_stop_does_not_start_a_new_run` (fails on 9f709a28).
2. **Defect in the program, notes shown as alerts in the Results summary** (fixed, `checks._SEVERE_WORDS`). The warnings of the models (`analytic`, `api`, `fvm`, `profiles`, `copper.model_warnings`) are still plain strings; `api.Simulation.warnings` gives them a severity through the old word list, which held `too hot`, `unsafe`, `unreliable`, `wrong`. So the Analytic copper-spread note (it quotes '9 % too hot') and the imported-copper `FILL_NOTE` ('7 to 10 % too hot') were drawn as alerts: on the harness boards `two_layer_partial`, `part_top_path`, `plate_pad`, and in the regenerated picture `results_summary_imported.png` (two triangles), against the maintainer's rule that a measured error is a note. The list now holds only failure words (`will not run`, `cannot`, `refus`, `not run`, `did not converge`, `did not settle`, `did not reach`, `heats nothing`, `runaway`): SOR not converging, the per-layer edge loop and the 3D solid not run stay alerts. The sweep test of the branch did not catch this because the summary wraps every plain string before the test looks (it checks that a severity exists, not where it came from). Test `tests/test_warning_severity.py::test_the_fallback_of_a_plain_model_string_follows_the_definition_of_an_alert`; `tests/test_theme_coherence.py` used 'unsafe' as its alert word and now uses a failure word. A run of the 17 harness boards: every input warning is explicit, every remaining word-classified run warning is a note.
3. **Defect in a test, order dependence** (fixed, `tests/test_warning_icons.py::_all_cases`). The alignment measurement left the application at 16 pt and the last theme; `tests/test_gui.py::test_docks_open_wide_enough_and_keep_the_run_button_in_sight` then failed (dock 310 against 420 px) when run after it. The font and theme are restored; the two files pass together (33 passed).
4. **Stale pictures** (fixed): `docs/images/results_summary_imported.png` regenerated after finding 2 (all notes now); `pcbthermal/help/editor_warnings.png`, the user guide's copy, was still the old picture with ⚠ and • (byte-identical to `docs/images` at 5bcaf57c): replaced by the regenerated one. `docs/images/editor_warnings.png`, `editor.png` and `results_summary.png` of the executor are right (neutral paths, the new badges, Run shown idle, never Stop). No other picture of `docs/images` or `pcbthermal/help` shows the Warnings rows or the old Cancel button (the others show the dock without warnings; `outline.png`, `stackup.png` and the like differ from a fresh run only by the 2.7.0 numbers of the status line, a release chore, not this branch).
5. **Stale document** (fixed): the guide said that Stop covers the Power Calculator; the calculator is modal, so the window's Stop cannot be clicked while it computes (the window shows Stop, and closing the calculator stops its job). The Run / Stop row now says so and mentions the short hold after a Stop; `CHANGELOG.md` and `docs/versions.md` carry the two review corrections.
6. **Limit to record**: the warnings of the models are still plain strings classified by words; a new model warning that names a failure in other words will be a note. Marking them at the source needs `warn` in a module that `analytic`, `fvm` and `profiles` can import without a cycle (`checks` imports them); a later item.
7. **Limit to record (pre-existing)**: in `results_summary_imported.png` the dock's `Warnings (5)` box has no rows (it is so in the `develop` picture too); not looked into here.
8. **Open for the maintainer**: which input warnings are alerts is the executor's reading of the rule. Borderline notes: a via outside the board ('ignored by every model'), a metal block that touches no copper ('takes almost no heat'), two heaters that overlap, a total power of zero. They are notes now.

## Checked and found right

* `gui/compute.py`: `_notify` after `submit`, `_finish`, `cancel`, the dead-process branch of `poll` and `shutdown`; `cancel_all` cancels the waiting jobs first (measured: simulation running, animation and analysis queued; cancelled in the order 1, 2, 0, no job started, no process alive, status 'Cancelled.' and 'Analysis failed: Cancelled.'); a cancel while the result already waits in the queue drops the result and leaves the state idle; a failing job gives Run back; closing the window (`shutdown`) emits idle.
* `main_window.py`: the toolbar swaps the actions at the end (Run is the last action), `a_run` is disabled while busy so F5 does nothing, `Ctrl+.` is unchanged, the memory block of the dock button never leaves it as Stop or disabled after a run (`_style_run_button` recomputes from `blocked`); the separate Cancel button is gone and nothing refers to it.
* The Power Calculator: its job makes the window show Stop; the cancel path stops it ('Cancelled.', Compute enabled again) and closing the dialog stops it (new test `test_the_power_calculator_job_shows_stop_and_is_cancelled`).
* Severity: every `_add` and `warn` has a severity, the maintainer's two examples (outside the board: alert; 9 vias under the footprint: note), the field survives pickling; no warning text changed (every string literal removed from `checks.py` and `api.py` is present again in the added lines).
* Badges: rendered offscreen at ratio 1 and 2, light and dark, an alert, an open note and wrapped titles: centred on the first line, the opened text indented under the badge, colours only from the `alert` and `muted` tokens, the cache keyed by kind, size, ratio and colour, redrawn from the current theme at each paint; the Results summary uses the same `WarningAccordion`.
