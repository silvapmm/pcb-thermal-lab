# The surface read-out: decisions (branch `feature/surface-always-both`)

Written for a future maintainer. One decision per line: what, why, what was rejected. The facts behind them are in `SURFACE_ALWAYS.md` (the reviewer's note, facts from the code and the per-model table), `SURFACE_NOTES.md` and `SURFACE_DOCS.md`; the code is `pcbthermal/thickness.py`, `analysis.surface_stats`, `api.surface_report_lines`, `plots.draw_surface`, `gui/results_view.py`.

Names: **column** = the layer mean through the copper (the node; for a part also the laminate face term under a source over absent copper). **Surface** = an estimate of the outer face of the copper (`T_m + t (2 q_top - q_bot)/(6 k)`).

| # | Decision | Reason | Rejected alternatives |
| :-- | :-- | :-- | :-- |
| 1 | The surface is a **view and a second number, never a mode** (no option, no project key, no CLI switch that changes a solve) | Tj, margin and the top path are read inside the solve loop; a read-out switch would let a display choice move the field | A mode switching the solved quantity: breaks like-for-like comparison of the models and the frozen numbers |
| 2 | **Always computed**, for every steady FVM/FDM result, every board, every thickness: the 105 um limit (`THICK_MIN_M`) is gone | The cost is 0 to 3 ms and three arrays of one layer field (272 kB on the example board at 1 mm); no frozen number reads the arrays; the 105 um limit existed only so that ordinary boards looked as before | Keeping the limit (a number that exists on some boards only is harder to trust and to test) |
| 3 | **Always shown** beside the column, no hidden threshold: `significant()`, `SHOW_ABS_K`, `SHOW_REL` are gone; a tiny difference is written out in K and in % of the rise (`+0.001 K, +0.002 % of the rise`) | A difference that appears and disappears with the board is a hidden rule; written out, it tells the reader that a thermocouple and the column agree on thin copper | Show only above max(0.1 K, 1 % of the rise) (the former rule: below it the difference is under the node's own discretisation error, but hiding it was not wanted); a Display switch 'Column / Surface' (a second way to the same view, meaningless on inner layers and the all-layers view) |
| 4 | **Graphs and maps draw the column mean** by default, named `column mean` in the title and the colour bar (`plots.COLUMN_LABEL`); the surface is the Layer-box entries `Surface (top/bottom)`, always listed | The column is the solved quantity, exists in every model and layer and in the transient, so the default picture compares like with like and matches the tables; the surface is an estimate of one face | Drawing the surface by default (not available in four models, not on inner layers, not in time); two maps side by side (halves the room for the one most users want) |
| 5 | The part table has **ONE surface column** (`Max °C (surface, estimate)`, the face of the part's source); the difference to the column max in K and % of the rise and the surface mean are in the **cell tooltip** | The columns of that table are already narrow and had been cut in a screenshot; the maximum is what is compared with a thermocouple; the tooltip keeps the detail without width | Two columns (mean and max): crowded; a third difference column: redundant with the tooltip |
| 6 | **Surface files only on request**: `run --surface-files` / `Simulation.save(surface_files=True)` write `surface_<model>.csv` and `surface_<model>_top/bottom.png`; the GUI saves the displayed Surface figure with the figure tool bar | Most runs do not need them; the numbers are always in `report.txt` and `summary.json`; the least invasive for the export dialog (no new control) | Writing them on every run (more files nobody asked for); a checkbox in the export dialog (a new control for a rare need) |
| 7 | **Tj, margin, power limit, top path, power coefficient, Power Calculator and calibration stay on the column** | They run in the solve and rest on a datasheet theta or psi measured on a board whose plate is already in the number: using the surface would count the plate twice | Moving them to the surface (double counting; a view would change a decision) |
| 8 | Models without it show **`n/a` with a tooltip** (Lumped, Analytic, 3D solid, a part on an inner layer); the transient, profiles and animations stay on the column with a note | Not hiding the column keeps the table the same for every model; the surface formula is quasi-static and was validated only in steady state | Hiding the column for those models (the table would change shape with the model) |
| 9 | Per layer type: outer copper = the formula; inner copper = the column (equal), no array; laminate = a node (resolved by sub-gaps); metal block = a node | An inner face is an interface with the laminate, where the temperature is continuous and no face flux defines a parabola | Computing an inner-copper surface (meaningless) |
| 10 | **The thin-copper trap is named**: on a patterned board the whole-face surface includes the bare laminate under a source (`laminate.face_terms`); 1.2153 K (`hatched_copper`) and 3.6458 K (`drawn_ell`) at 1 mm on 35 um copper, while the part rows read +0.000 K because their column already holds that term | The comparison of the whole face with the node maximum mixes two things; the user must not read a copper effect into it | Gating on `surface_excess_k` (it would have shown the surface only on those two boards, for the wrong reason); subtracting the laminate term from the face (changes what the face means) |
| 11 | The report line compares each face with the column of **its own layer** (top: layer 1, bottom: the last layer), not with the board maximum | The first draft compared the bottom face with the board maximum and printed -23 K; found when the thin-copper report was read | Comparing with `res.t_max` |

## Per model: what is given and what could come

| Model | Today | What could come (effort) |
| :-- | :-- | :-- |
| FVM, FDM steady | the estimate, always | - |
| FVM, FDM transient, profiles, animation | column, with a note | an offset per step from the step's fluxes; not validated against a 3D transient (M-L, medium); recommended: keep the column |
| Lumped | n/a | a bracket `q t/(3k)` to `q t/(2k)` shown as a bound, not an estimate (S); a real estimate: no |
| Analytic | n/a | the same parabola from the series' own interface fluxes; not derived for the local via and heatsink corrections (M, needs a check against the independent 3D) |
| 3D solid | n/a (one cell per copper slab) | the parabola from its fluxes (S) or several slabs through thick copper (S-M, changes the memory law) |
| FEM | not yet selectable here; the branch under review fills the same arrays | computed, not estimated (the reference for the estimate); the hook is `arrays["T_surface"]`, `T_surface_mean`, `T_surface_flag` and `extras["t_max_surface_*"]` |

## What was checked (this tree)

* Thin copper, 20 boards of the frozen set, FVM and FDM at 1 mm: surface minus column max under the part +0.4 to +3.2 mK; example board +1.3 mK. Patterned boards: see 10.
* Face-flux balance over an insulated-edge plate at 0.035, 3 and 10 mm: |net| below 3e-10 W.
* No number moves: the non-surface numbers are bit-identical with `thickness.attach` switched off (`test_thin_copper_has_the_surface_tiny_but_present_and_nothing_else_moves`); a saved project is byte-identical; frozen numbers: see the run recorded in `SURFACE_ALWAYS_NOTES.md`.
