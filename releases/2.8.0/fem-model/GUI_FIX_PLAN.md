# Plan: fixing every finding of the general GUI review (2.8.0)

Source: `GUI_GENERAL_REVIEW.md` (same folder; defects D1 to D12, improvements 1 to 10, and the text of its sections 2 to 7). The maintainer asks for **everything** to be fixed. The 'for 2.9.0' items are fixed too where they are cheap and safe; only what needs a larger design is left out, and that is listed in section 6. Units follow the proper symbols everywhere (°C, µm, ×). **Maintainer's unit rule**: `°C` for temperatures **and** for temperature differences and rises (`ΔT °C`, margin in °C, 'x °C above its limit'); `K` only inside compound units (`K/W`, `W/m·K`, `K·cm²/W`). This supersedes the `ΔT K` of `SUMMARY_TABLE_REVIEW.md` and of the general review.

Three branches, all from `development`:

* **A** `feature/gui-panel-polish` (executor, worktree `.claude/worktrees/gui-panel`): the Simulation panel and the window chrome.
* **B** `feature/gui-results-warnings` (executor, worktree `.claude/worktrees/gui-results`): the Results tab, the warnings and the pages that are cut.
* **C** `fix/gui-review-rest` (the reviewer implements it): everything else, started **only after A and B are merged into `development`**.

Effort: S = hours, M = a day or two, L = more. Every 'Test' is a new or extended pytest (offscreen) unless an existing test is named. 'Shot' names the screen of the final screenshot set (section 5) that shows the fix.

## 1. Order and dependencies

1. **A** first. It defines what B and C reuse: the one table of model names (`results.MODEL_LABELS` with a long and a short form), the theme tokens (`accent_text`, the darker light `warn_text`, the `on_accent` fix, the `field_border`) and the painter of the coloured dot (`theme.dot_pixmap`).
2. **B** next. It merges the new `development` before it starts its own commits that touch `theme.py`, `tips.py` and `help/index.html`. It uses A's name table and dot painter: it does not define its own.
3. **C** last, from the `development` that holds A and B. It ends with the units and typography scan test (section 3) and the one set of screenshots (section 5).

Each branch goes executor (or reviewer for C), then reviewer, then maintainer, with the whole battery before its merge (`CLAUDE.md` 6). No number moves: there are no pending files and the frozen numbers are unaffected. The text of `report.txt` changes (B), which the reproduction pass must know about.

Files touched by more than one branch (conflict risk, hence the order): `gui/panels.py` (A: `SolverPanel`; B: `_element_name`; C: the Properties panel only if B left something), `gui/theme.py` (A defines, B and C use), `gui/tips.py`, `help/index.html` section 8, `tests/test_gui_stress.py`, `tests/test_help.py`, `CHANGELOG.md`, `docs/versions.md`, `docs/decisions-log.md`. **Screenshots are not regenerated by A or B for the README**; only C makes them, once (section 5). ## 3. Units and typography: one rule

**Rule.** On screen, in the guide and in the human reports, quantities take their proper symbols; files read by programs (CSV, JSON, project files) keep ASCII column names and plain numbers. One formatter for numbers (`numfmt.num`, `numfmt.eng`, `numfmt.signed_fixed`); no f-string formats a temperature or a unit in a view on its own.

| Form | Write | Not | Where the old form is today | Note |
| :-- | :-- | :-- | :-- | :-- |
| temperature | `°C` | `degC`, `C` | `api.py` (21 visible strings, text report and run notes), `cli.py` (9), `checks.py` (2), `thickness.py` (1), `gui/tips.py` (1) | docstrings may keep `degC` (not visible) |
| temperature difference, rise, margin | `°C` (`ΔT °C`, `Margin °C`, '+0.4 °C above the column') | `ΔT K`, `dT C`, a bare `K` after a difference | `api.py:331` (`dT C`), Components header 'Margin K' and surface tooltips (`results_view.py`, `api.surface_report_lines`), run notes and warnings ('90.4 K above its limit', `api.py`, `checks.py`), memory and FEM texts quoting K differences | B3, B5; `K` stays only inside `K/W`, `W/m·K`, `K·cm²/W` |
| thermal resistance | `Rθ K/W` | `Rth K/W` | `api.py:331` | `Rth j-sp` in the tooltip of θ junction-pad is a datasheet name and stays |
| micrometre | `µm` (U+00B5) | `um` | import window step 1 ('35 / 35 um copper'), `model.py:172` derived stack-up name | C9; `um` in docstrings and variable names stays |

## 6. Main risks

* **Conflicts between A and B** in `panels.py`, `theme.py`, `tips.py`, the guide and the stress test: kept small by the order (A first) and by the split of `panels.py` (A owns `SolverPanel`, B owns `Inspector` and `_element_name`).
* **Old strings in tests**: about ten test files assert texts that change (labels, report columns, warning button, menu entries); each branch updates its own, and the scan test (C17) comes last so that it does not block A and B.
* **The text report changes** (B3, B5): scripts that read `report.txt` would break; `summary.json` and the CSV files keep their keys. The research folders that parse the report must be checked in the reproduction pass.
* **Clearing the results on load** (A7): a test or a script that loads a problem after `_on_done` and expects the old results would now see the empty state; `examples/make_screenshots.py` runs `_on_done` after each load and is unaffected.
* **Native macOS fonts** are wider than the offscreen ones: the no-cut tests run offscreen; the final set must be looked at on the maintainer's machine too.
* **Scope creep in C**: C holds 19 items, most S; if C grows past two days, C11, C15 and C16 go to a second pass and are recorded in 'Planned'.
