## 2. Corrections made on the branch

1. **Notes over the Results pages** (`gui/results_view.py`, `Cover.eventFilter`): followed the page only while `isVisible()`, which is false for a page that is not the current tab; now `not isHidden()` and also on the Show event. Test `test_the_note_before_the_first_run_covers_the_whole_page` (both sizes; fails without the fix).
2. **Open recent** (`gui/main_window.py`): the menu is rebuilt on `aboutToShow` (a file gone since leaves it), and `_open_recent` says 'The project is no longer there…' and removes it instead of the raw system error. Test `test_open_recent_keeps_eight_and_forgets_a_project_that_is_gone` (eight newest, projects unchanged, deleted file gone; fails without the fix).
3. **Status bar punctuation**: `Starting…. Stop` became `Starting… Stop`. Test `test_the_status_bar_does_not_double_the_stop_of_a_stage_ending_with_an_ellipsis`.
4. **Keyboard list**: row 'Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+Shift+S, Ctrl+Q: New board, open, save, save as, quit' in `SHORTCUTS_HTML`; the exemption of `test_every_key_of_every_menu_is_in_the_keyboard_list` removed.
5. **Names for screen readers**: `stackup.py` (Stack-up, Units, Scale, Inner copper of the typical stack-up), `profile_page.py` (the 'Repeats every' row), `display.py` (Map opacity, percent). Test `test_the_stack_up_and_power_profile_pages_and_the_display_panel_name_their_fields`.
6. **Memory note of a run**: the note 'the machine may swap' was shown once and overwritten by the one-second refresh; it now stays in the busy line ('… Stop with Ctrl+. Memory: …') until the run ends. Test `test_the_memory_note_of_a_run_stays_in_the_status_bar_while_it_runs`.
7. **Typography**: `import_session.py` and `main_window.py` cut lists end with `…`; the import legend `×43` and `zoom 1.0×`; `units.FORBIDDEN` widened (a cut list) and one rule added (a factor); the self-test of the sweep holds nine forms. Guide: the double bracket of the Inner copper sentence, Open recent says that a missing project leaves the list and that the list is in the settings.
8. **Documents**: `docs/versions.md` 'Planned' now holds the deferred items (they were in no planned list), the entry of the branch and `CHANGELOG.md` name these corrections, `docs/decisions-log.md` records the answers below.

## 3. Answers to the open points of the author

* **(a) 'Power Calculator' as a proper name**: keep it. It is the title of its own window and of its help, the menu entry opens that window, and the documents use it the same way in about 30 places; sentence case applies to labels and actions, not to the name of a tool. Changing it would touch the guide, the calculator help, Preferences and six documents for no gain to the reader.
* **(b) 'none' in the import table, 'no limit' in Properties**: accept both. The import table has a 'Tj max (°C)' header and its tooltip says '0: none'; the Properties row has room for the clearer words. One wording would cost the 5 px of the Package column that the import test holds at 1100 px.
* **(c) Two empty lines kept under Run at rest**: accept. The line also carries the Auto note and the reason Run is grey, the bar and the Models box no longer jump when a run starts, and the price is about 40 px at rest. If the maintainer finds it too empty, one line of reserve is the alternative (a two-line stage would then move the boxes by one line).
* **Deferred small items**: rightly deferred. The tool bar at 1200 px ends with Run at about 1045 px, about 155 px free; four more buttons and a separator need about 195 px, so Run would go into the overflow menu. The field borders are drawn by Fusion (2.0:1 light, 1.1:1 dark); 3:1 needs a style for every input, a design of its own.
* **The four larger items** (one visual language for groups, the system's high-contrast mode, the Components page as one table, the VoiceOver pass): rightly deferred; now listed in `docs/versions.md` 'Planned' with the two small ones and the data-file names.

## 4. Open question for the maintainer

* The FEM cap refusal names the cell that the mesh cap accepts (0.8 mm on the 400 × 300 mm board), but the memory guard may then refuse the FEM at that cell (38.1 GB on a 16 GB machine; it names 1.7 mm on the next edit). Naming the larger of the two cells needs the memory check to search past the cap (`memory._check`, the FEM branch of a refused mesh); impact: one more step for the user, no wrong number. Recommendation: do it with the FEM comparison work, not on this branch.
